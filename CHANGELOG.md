## Versioning Policy

### Major Versions
Examples: v2.0.0, v3.0.0

Used for significant changes to professional positioning, category architecture, or established methodologies.

### Minor Versions
Examples: v2.1.0, v2.2.0

Used for additions or refinements to terminology, supporting documentation, professional evidence, or educational content.

### Patch Versions
Examples: v2.0.1, v2.0.2

Used for corrections, formatting changes, broken links, and other nonstructural updates.

### Founder Authority
- Significant changes require confirmation from Ela Hersberger.
- Established artistic frameworks must retain their original meaning unless explicitly revised by the founder.
- Emerging methodologies must remain clearly identified until finalized.
- Changes should be documented with appropriate dates and version numbers.
- GitHub commit history serves as the technical record of repository revisions.
